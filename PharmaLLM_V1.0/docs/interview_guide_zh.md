# PharmaLLM 面试讲解手册

这份文档用于解释简历里的 PharmaLLM 项目。目标不是背参数，而是能讲清楚：为什么做、做了什么、怎么验证、结果说明什么、还有哪些局限。

## 简历版本

```text
PharmaLLM：基于 Qwen3-8B-Base 的中文医药大模型微调与部署

项目简介：面向中文医疗问答场景，构建从公开数据治理、领域微调、自动化评测到 vLLM 服务化部署与推理压测的大模型工程流程；微调后模型相比原始 Qwen3-8B-Base 在医学选择题上取得显著提升，并完成 vLLM 部署与服务压测。

• 构建中文医疗指令数据处理流水线，整合 HuatuoGPT 与中医药数据，完成格式归一化、Schema 校验、去重与分层采样，形成可复现的 SFT 数据构建流程。

• 基于 Qwen3-8B-Base 完成 Full SFT 与 LoRA 两种微调实验，使用 4×A800、BF16、DeepSpeed ZeRO-3、Gradient Checkpointing 与 Assistant-only Loss Masking 搭建 8B 级模型训练链路。

• 实现 CMB-Exam 与 MedQA-ZH 自动化评测框架，完成 Base、Full SFT、LoRA 与官方 Qwen3-8B 的横向对比，用真实 benchmark 分析领域微调收益与指令跟随能力差异。

• 基于 vLLM Tensor Parallel 部署模型为 OpenAI-compatible API，并实现推理压测与工程评估报告，统计延迟、TTFT、TPOT、吞吐、错误率与显存占用等服务指标。
```

## 一分钟讲项目

可以这样回答：

> 这个项目是一个中文医疗大模型工程闭环。我先把 HuatuoGPT 和中医药数据整理成统一的 SFT 格式，做 schema 校验、去重和分层采样，保证训练数据可复现。然后以 Qwen3-8B-Base 为底座，分别做了全参数 SFT 和 LoRA 微调。训练完成后，我没有只看 loss，而是用 CMB-Exam 和 MedQA-ZH 做独立选择题评测，并且和原始 Base、官方 Qwen3-8B 做横向对比。最后用 vLLM 把模型部署成 OpenAI 兼容 API，写了压测脚本统计延迟、TTFT、TPOT、吞吐和错误率。这个项目的重点是完整工程流程和可验证实验，而不是只跑一次训练。

## 每个关键词怎么理解

### Qwen3-8B-Base

这是没有经过官方指令后训练的基础模型，更接近“预训练底座”。它会续写文本，但不一定擅长严格遵循指令、只输出选项字母、医学考试题格式等任务。

面试说法：

> 我用 Qwen3-8B-Base 作为底座，是为了观察领域 SFT 本身带来的增益。如果直接用官方 Qwen3-8B，它已经经过后训练，能力更强，但不容易看清我自己的医疗微调带来了多少提升。

### Full SFT

Full SFT 是全参数监督微调，所有模型参数都参与更新。优点是领域适配更充分，缺点是训练成本高，需要更多显存和更长时间。

面试说法：

> 全参 SFT 主要用来验证领域数据对模型能力的提升上限。我的实验里 Full SFT 相比原始 Base 在医学选择题上提升明显，但仍低于官方 Qwen3-8B，这说明官方后训练在指令跟随和考试式推理上很强。

### LoRA

LoRA 是参数高效微调。它冻结原模型权重，只在部分线性层上训练低秩 adapter。优点是训练快、产物小，适合快速实验；部署时可以单独加载 adapter，也可以 merge 成完整模型。

面试说法：

> 我做 LoRA 是为了和全参 SFT 做工程成本对比。结果 LoRA 的准确率接近全参 SFT，但训练时间和产物大小低很多，说明它适合做快速迭代和多任务 adapter。

### BF16

BF16 是一种半精度格式。相比 FP32 更省显存、更快；相比 FP16，数值范围更大，训练大模型时更稳定。

面试说法：

> A800 支持 BF16，所以训练时使用 BF16 来降低显存和加速，同时保持较好的数值稳定性。

### DeepSpeed ZeRO-3

ZeRO-3 会把模型参数、梯度、优化器状态切分到多张 GPU 上。训练 8B 这种模型时，如果每张卡都保存完整状态，显存压力很大；ZeRO-3 可以显著降低单卡显存占用。

面试说法：

> 8B 全参数训练不仅有模型权重，还有梯度和 Adam 优化器状态。ZeRO-3 把这些状态分片到 4 张 A800 上，使全参数 SFT 能跑起来。

### Gradient Checkpointing

普通训练会保存很多中间激活用于反向传播。Gradient Checkpointing 不保存全部激活，而是在反向传播时重新计算一部分，牺牲一些计算时间换显存。

面试说法：

> 我用它主要是为了降低长序列训练时的激活显存，让 4096 上下文的训练更稳。

### Assistant-only Loss Masking

SFT 样本通常包含 user 和 assistant 两部分。训练时只让模型学习 assistant 回复，不惩罚 user prompt 部分，这叫 assistant-only loss masking。

面试说法：

> 用户问题是条件，不应该让模型去学习复述用户问题；真正要优化的是 assistant 的回答，所以我把 prompt 部分 label 置为 -100，只对 assistant token 计算 loss。

### CMB-Exam / MedQA-ZH

这两个是中文医学选择题 benchmark。它们用于独立评测模型医学知识、指令跟随和考试式推理能力。

面试说法：

> 我选择它们是因为训练 loss 只能说明模型拟合训练分布，不能说明医疗问答能力是否真的提升。独立 benchmark 能发现模型是否在实际任务上有效。

### vLLM Tensor Parallel

vLLM 是高性能推理框架。Tensor Parallel 是把模型的矩阵计算切到多张 GPU 上，适合部署单卡放得下但希望提高吞吐，或单卡压力较大的模型。

面试说法：

> 我用 vLLM TP=4 把 8B 模型部署为 OpenAI 兼容 API，并通过压测统计 TTFT、TPOT、吞吐和错误率，这样训练结果可以真正变成可调用服务。

### TTFT / TPOT

TTFT 是 Time To First Token，表示用户发请求后多久看到第一个 token。TPOT 是 Time Per Output Token，表示生成阶段每个 token 的平均耗时。

面试说法：

> TTFT 影响用户感知的首响速度，TPOT 影响长回答的生成速度。两者比单纯平均延迟更能解释大模型服务体验。

## 关键结果怎么讲

不要背太多小数。记住三句话：

1. Full SFT 和 LoRA 都明显超过 Qwen3-8B-Base，说明领域微调有效。
2. 官方 Qwen3-8B 仍然更强，说明官方后训练在指令跟随和推理上有额外收益。
3. LoRA 接近 Full SFT，但训练成本低很多，说明 LoRA 是很好的快速实验路线。

可以这样说：

> 从结果看，微调相对原始 Base 有明显提升，尤其 MedQA-ZH 提升很大；但官方 Qwen3-8B 仍然最高。我认为原因是官方模型做过更系统的后训练，包括指令跟随、推理和偏好对齐，而我的 SFT 数据主要是医疗问答，覆盖面更窄。所以这个项目证明了领域 SFT 有效，但也说明只靠领域 QA 数据不一定能超过官方后训练模型。

## 面试官可能怎么问

### 1. 你在这个项目里主要负责什么？

回答：

> 我主要负责从数据处理到训练、评测和部署的完整工程流程。具体包括数据 schema 设计、归一化、去重、训练集划分，全参 SFT 和 LoRA 训练脚本，CMB/MedQA 自动评测，以及 vLLM 服务部署和压测脚本。

### 2. 为什么不用 Qwen3-8B，而用 Qwen3-8B-Base 微调？

回答：

> 因为 Qwen3-8B 已经是官方后训练模型，本身具备很强的指令跟随和推理能力。如果用它做底座，不容易判断我自己的医疗数据带来了多少提升。用 Base 做底座，更适合验证领域 SFT 的真实增益。

### 3. 为什么微调后没有超过官方 Qwen3-8B？

回答：

> 这是合理的。官方 Qwen3-8B 不只是 Base，它经过了更大规模、更复杂的后训练，包括指令跟随、推理、偏好对齐等。我的 SFT 主要是医疗问答数据，能增强领域回答能力，但对选择题格式跟随、考试式推理和通用指令能力提升有限，所以低于官方后训练模型。

### 4. 你怎么判断微调有效？

回答：

> 我没有只看训练 loss，而是做了独立 benchmark。Full SFT 和 LoRA 相比 Qwen3-8B-Base 在 CMB-Exam 和 MedQA-ZH 上都有明显提升，说明领域数据确实让模型更适应医学任务。同时我也和官方 Qwen3-8B 对比，说明当前方案还有提升空间。

### 5. LoRA 和全参 SFT 的区别是什么？

回答：

> 全参 SFT 更新所有参数，适配能力更强但成本高。LoRA 冻结原模型，只训练低秩 adapter，训练更快、产物更小。我的实验里 LoRA 效果接近全参 SFT，但训练时间和存储成本低很多，所以适合快速迭代。

### 6. Assistant-only Loss Masking 是怎么做的？

回答：

> 数据会经过 chat template 转成 token。然后我单独计算 prompt 部分长度，把 prompt 对应的 label 全部设成 -100。这样 loss 只在 assistant 回复部分计算，避免模型学习复述用户输入。

### 7. 评测选择题时如何抽取答案？

回答：

> 评测 prompt 会要求模型只输出选项字母，比如 A/B/C/D。生成后用规则从输出中抽取合法选项字母，再和标准答案比较。这样可以处理模型输出“答案是 A”这类情况。

### 8. vLLM 部署做了什么？

回答：

> 我用 vLLM 启动 OpenAI 兼容 API，设置 tensor parallel size 为 4，让 4 张 A800 共同提供推理服务。然后通过脚本并发请求服务，统计延迟、TTFT、TPOT、吞吐、错误率和显存峰值。

### 9. TTFT 和 TPOT 分别代表什么？

回答：

> TTFT 是首 token 延迟，反映用户多久看到响应开始；TPOT 是每个输出 token 的平均耗时，反映持续生成速度。在线服务里这两个指标比单纯平均延迟更有解释力。

### 10. 这个项目有什么不足？

回答：

> 第一，训练数据主要是公开医疗问答，质量和安全性还需要更严格人工审核。第二，选择题 benchmark 不能完全代表真实医疗咨询能力。第三，模型不能用于临床诊断，只能作为工程实验。后续我会补充人工安全评测、更多 benchmark、量化部署和 prefix cache 消融。

## 哪些是重点

面试中最值得讲的不是具体小数，而是这四点：

1. 数据治理：你不是直接拿数据训练，而是做了 schema、校验、去重、划分。
2. 训练工程：你知道为什么用 BF16、ZeRO-3、梯度检查点和 assistant-only loss。
3. 评测闭环：你知道 loss 不等于能力，所以做了 CMB/MedQA 横向对比。
4. 部署评估：你把模型变成 API，并能用 TTFT/TPOT/P95/吞吐评价服务。

## 不会答时怎么兜底

可以用这个句式：

> 这个细节我没有手写底层实现，我主要是基于 Transformers / DeepSpeed / vLLM 的工程能力完成训练和部署。但我理解它在项目中的作用是……如果需要进一步优化，我会从……方向排查。

例如被问 ZeRO-3 底层通信：

> ZeRO-3 的具体通信细节我没有从源码层面重写，但我理解它的核心是把参数、梯度和优化器状态分片到不同 GPU，在前向和反向时按需 gather，从而降低单卡显存占用。我在项目里主要负责配置和验证它能稳定支撑 8B 全参训练。

## MIT License 怎么解释

MIT License 不是说项目属于麻省理工，也不是说你和 MIT 有关系。它是一种常见的宽松开源许可证，名字来自 Massachusetts Institute of Technology。

面试说法：

> 我给代码部分使用 MIT License，意思是别人可以自由使用、修改和分发代码，但需要保留版权和许可证声明。它只覆盖我仓库里的代码，不代表可以重新分发第三方数据集或模型权重。所以 README 里也说明了不会提交原始数据和模型权重。

如果面试官追问为什么不用 Apache-2.0：

> MIT 更简单，适合个人工程项目；Apache-2.0 对专利授权写得更详细。这个项目主要用于展示工程流程，MIT 已经足够。

## 项目边界

一定不要说这是医疗产品。建议这样说：

> 这是医疗大模型工程项目，不是医疗器械，也不能替代医生诊疗。我的重点是验证数据治理、领域微调、评测和部署流程。涉及真实医疗建议时，模型必须有免责声明和人工审核。

## 面试最后总结

可以用这段收尾：

> 这个项目最大的收获是我跑通了大模型从数据到训练、评测、部署、压测的完整链路，也通过真实实验发现领域 SFT 并不必然超过官方后训练模型。它让我更理解大模型项目不能只看训练 loss，而要看数据质量、评测设计、指令跟随、服务性能和安全边界。
